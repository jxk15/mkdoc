    滑动窗口协议¶

    OSI 的观点：无重复、无乱序：帧编号；无丢失：确认、（超时）重传机制。

    数据链路层存在 3 种协议可以在引导型传输媒体提供可靠传输。

    • 停止等待
    • 后退 N 帧
    • 选择重传

    停止等待(SW)协议¶

    窗口大小：发送窗口、接收窗口均为 1

    后退 N 帧(GBN)协议¶

    确认帧：x，表示 x 及以前已正确接收。

    接收方采用累积确认方式，且期望按序接收分组。

    • 丢失：某帧丢失后，后续的帧也不接收。
    • 乱序：发生乱序及其后续的帧不接收。
    • 确认帧丢失：发送方超时重传；接收方不接收重复帧（无所谓丢失、乱序），对非重复帧按序接收。

    对窗口的限制：

    • 发送窗口：小于 \(2^n\)
    • 接收窗口：1

    确认帧：逐一确认（选择确认）。

    为了增加接收方的接受效率，增加了接收窗口的大小：处理乱序情况。

    滑动机制：发送方收到确认帧后，能滑则滑；接收方发出确认帧后，能滑则滑。（表述不清，先这样了

    确认帧丢失：触发超时重传，接收方收到重传帧后重新发送确认帧并丢弃重复帧。

    怀疑帧机制

    Note

    1. 为什么丢弃重复帧？
      • 从网卡交付给上层，会占用内存总线。
    2. 理论与现实
      • 在选择重传下，接收窗口和发送窗口不相等，理论上是可行的，但没办法实际应用。实际中接收窗口 \(=\) 发送窗口。

    信道利用率¶

    发送周期：发送方从发送第一个 bit 开始，到接收第一个确认帧为止。

    信道利用率：发送方在一个发送周期内，有效地发送数据（完整发出且正确接收的帧）所需要的时间占整个发送周期的比率。

    信道吞吐率：数据实际的传输速率。即数据传输速率 * 信道利用率

    以太网¶

    无确认无连接服务：源机器发送数据帧时不需要先建立链路连接，目的机器收到数据帧时不需发回确认。对丢失的帧，数据链路层不负责重发，由上层处理。

    CSMA/CD 协议¶

    有确认帧的情况，不用做冲突检测。虽然以太网不是可靠传输，但是冲突概率太大，有必要做冲突检测。（在没有冲突时，基本能成功发送，相信信道的稳定性）

    CSMA/CD 协议：载波侦听多路访问/冲突检测协议，半双工

    争用期 \(\tau\)：2 * 传播时延

    二进制退避算法¶

    为什么退避时间的基本单位是争用期？

    碰撞双方开始退避的时间不一样。

    假设 A 发出的帧几乎到达 B 时，B 开始传输。B 检测到碰撞后开始退避，A 会在 0.5 \(\tau\) 后开始退避。

    若基本单位为 \(\tau\)，当 A、B 退避时间相等或 B 比 A 多一个单位，再次碰撞。

    若基本单位为 0.5 \(\tau\)，当 A、B 退避时间相等或 B 比 A 多一、二个单位，再次碰撞。

    从概率上说选取 \(\tau\) 更好；当退避使得 A、B 不冲突时，剩余的退避时间也没意义了，这时 0.5 \(\tau\) 和 \(\tau\) 的区别没有进一步的影响。因此基本单位选用 \(\tau\)。

    VLAN¶

    在典型交换网络中，当某台主机发送一个广播帧或未知单播帧时，该帧会被泛洪。可以采用路由器或 VLAN 交换机解决。

    IEEE 802.1Q 帧：4 字节的 VLAN 标记（tag）

    802.1Q 帧是由交换机来处理的，不是由用户主机来处理的。当交换机收到普通的以太网帧时，会将其插入 4 字节 VLAN 标记进而转变为 802.1Q 帧，简称“打标签”。
